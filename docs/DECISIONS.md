# Decisions

Settled decisions and why, newest ids last. Ids are `W-nnn`; `D-nnn` refers to the Tamale repo's register.
"Proposed" means the planning agent recommended it on 2026-10-08 and the owner has not yet confirmed it.
"Owner" means the owner asked for it. Don't relitigate a confirmed decision; if one looks wrong, say so and ask.

| Id | Decision | Why | Standing |

| W-001 | A scheduled pipeline, not an always-on agent | Cheaper and auditable; a model is used only to read letters and write summaries | Proposed |
| W-002 | Public data only, in its own project and repo; firm-side consumers are built in the Tamale repo | The ingest job fetches untrusted content from the internet, so it must not sit beside Tamale or APX credentials. A deliberate exception to D-045 (one repo and image for Tamale workloads) | Proposed |
| W-003 | Postgres is the system of record; Tamale is an output | Tamale is a notes system, not a query engine; overlap and change questions need SQL | Proposed (owner suggested storing in Tamale; summaries still go there) |
| W-004 | Database `whales` (and `whales_dev`) lives on the existing server `pg-tocqv-context`, under these conditions, all done before the ingest job first connects. (1) `REVOKE CONNECT ON DATABASE context FROM PUBLIC`, made in the Tamale repo's `scripts/context_db_roles.py`, which today grants CONNECT to `context_writer` but never revokes it from PUBLIC. (2) The same for `whales` and `whales_dev`, and no CREATE on their `public` schemas. (3) The ingest identity gets CONNECT on `whales` only and is never a member of any Tamale role; consumers get `whales_reader` (SELECT on `api`). (4) No secret, connection string or role is shared between the two projects. Move to its own server if load, an incident or a compliance view calls for it; that is a dump and restore, since the data is small and rebuildable | The owner asked for the existing server or something extremely cheap (2026-10-08). A separate Burstable B1ms costs about $12 a month compute plus about $4 storage (third-party trackers, not checked against Microsoft). The data is small and public, and the workload a weekly batch. The isolation gap (any login role could reach `context`) is closed by condition 1, which Tamale needs anyway. Residual risk: a server-level Postgres flaw or an admin mistake could cross databases. The server also stays in Central US while the job runs in East US, which is fine for a batch | **Owner (2026-10-08)**: share the server, with the conditions |

| W-024 | A manager is a set of filer CIKs, each with the quarters it counts for (`core.filer`). A manager's quarter is the union of its filers' 13F-HR lines. Duplicate filings are excluded by listing them in config. If two of one manager's filers report the same entry count and value total for a quarter, the ingest stops and asks | The 2026-10-08 survey found successions (Greenlight to DME, JANA LLC to JANA Management, Pershing Square Capital Management to Pershing Square Inc.), parallel books (Fundsmith) and one identical double filing (Situational Awareness 2026 Q1). See `docs/MANAGER_SURVEY.md` | Proposed |
| W-025 | Detect 13F value units for each filing, never by filing date alone. For each share line, implied price is value divided by shares; compare it with the median for the same CUSIP and quarter across all filers in the SEC bulk data set. Near 1/1000 of that median means the filing is in thousands; ambiguous means refuse and flag | Baupost and Duquesne still report in thousands in 2026, and the summary-page reconciliation cannot catch it | Proposed |
| W-026 | Ingest every verified candidate (30 managers, about 32 filers), tagged by style cohort (technology and growth; value and quality; activist; macro and credit), and run overlap reports within and across cohorts rather than limiting the watchlist to 20. Leave Whitebox out (W-010) | 13F volume is tiny, so a smaller list saves almost nothing. The noise risk is in mixing styles, which cohorts handle | Proposed; owner to confirm. **Cohorts superseded by tags (W-038)** |
| W-027 | Shareholder letters are the primary product; 13F holdings are a supporting layer | The owner, 2026-10-08: "the real value is going to be in the shareholder letters". 13F tracking is a commodity that existing tools such as WhaleWisdom already do | Owner |
| W-028 | Keep the 13F layer thin and built from public SEC data: the bulk data sets for backfill and the filing XML for new quarters. Check it against WhaleWisdom as an independent verifier, rather than buying WhaleWisdom as the source | Holdings are still needed for the said-versus-owned comparison and for the Research Assistant's joins to APX. Building from SEC data keeps them in the public tier, while WhaleWisdom's terms on storing and redistributing its data are unreviewed. WhaleWisdom's API: an account with signed key pairs, 20 requests a minute, the last 8 quarters without a subscription, subscriptions about $360 to $600 a year (secondhand prices, unconfirmed). The verifier idea is the owner's | Proposed |
| W-029 | Letter sources come in four tiers, recorded on every document. (1) Published by the manager or its listed or mutual-fund vehicle. (2) SEC filings, such as activist letters filed with a 13D or as proxy material. (3) A third party republishing letters written to partners (for example Hedge Fund Alpha); used only under a licence or written permission from that party and a compliance ruling. (4) Received as an LP: restricted (W-014) | The owner's examples (Greenlight Q2 2026 and Stone Sentinel Q3 2026 on hedgefundalpha.com) are tier 3. Each is a letter to partners on a subscription site ($399 a year) marked "All Rights Reserved", with no public terms page. Its robots.txt allows fetching and declares `ai-input=yes, ai-train=no`, but that is not permission to store or redistribute. Tier 3 is the broadest and most timely source, so asking for a licence is worth it | Proposed; compliance to rule |
| W-030 | Record each PDF's permission flags. A document whose flags forbid text extraction is not machine-read without a compliance ruling | The Greenlight Q2 2026 PDF on Hedge Fund Alpha is encrypted with copying and text extraction disallowed (permissions value -1052; print and accessibility extraction allowed). Overriding that in an automated pipeline is a legal question (anti-circumvention), not an engineering one | Proposed; compliance to rule |
| W-031 | Pull Schedule 13D and 13G filed by watchlist filers only (never all filers on a company). 13D and its amendments, with exhibits, join the letters pilot; 13G joins the 13F layer. Match both the old and the new form names (`SC 13D`, `SC 13G` before 2024-12-18; `SCHEDULE 13D`, `SCHEDULE 13G` after) | Activists' letters to boards are filed as 13D exhibits: tier-2 letters, plainly public. The 13D's purpose section is the manager stating intent. Both forms are far timelier than 13F (13D within 5 business days, amendments within 2). Starboard filed 49 13D forms between 2024-01-01 and 2026-10-06 | Proposed (owner asked whether 13G is pulled) |
| W-032 | For letters, keep the raw file only where the source's terms allow storing it. Otherwise keep the URL, content hash, fetch date, extracted metadata, short quotes and summaries (W-015), and re-fetch when needed. Record the permission basis on every `letters.document` | Some tier-1 sources reserve storage: PM Capital's parent, Regal Partners, requires prior written consent to store any of its website content. This amends the rule that the database must be rebuildable from blobs: for such sources it is rebuildable by re-fetching, while the source still serves the file | Proposed; compliance to rule |
| W-033 | Each letter source has a collection mode. **auto**: the collector fetches and extracts, keeping the raw file only if terms allow (W-032). **manual**: no automated access to the site at all. The system works out when the next letter is due from the source's cadence and its past publication lag, and reminds a named person until the letter is loaded, marked not yet published, or skipped. The person downloads it and drops it into the intake, and the ingest job does the rest. Sources behind a form, login or attestation are always manual, even when the files can technically be reached | Owner, 2026-10-08: "we don't necessarily have to scrape the letters if not possible, but in that case we would need an automated reminder to check". Most publisher terms ban bots or allow only personal use (see `docs/LETTER_SOURCES.md`), so even checking an index page for changes is automated access. A calendar needs no site access | Owner asked; mechanism proposed |
| W-034 | Reminders and the weekly digest go to a Teams channel through a Teams Workflows (Power Automate) flow triggered by "When a Teams webhook request is received", posting Adaptive Cards. The flow URL is a secret: Key Vault in Azure, `.env` locally. The digest runs Monday morning US Eastern and lists letters due or overdue (manual sources), letters loaded since last week (auto sources), and failing or stale sources. Reminders go to a role, `letters_reviewer`, set in config: the owner for now, later an intern or junior analyst, with no code change. Overdue items repeat every week until loaded, marked not yet published, or skipped | Owner, 2026-10-08: "Teams digest, and I'll act on the reminders (for now, but should likely go to an intern or lower level analyst)". Microsoft retired Office 365 connectors, including the classic incoming webhook, on 2026-05-18 to 22; Workflows is the supported route. It needs no Graph secret, unlike the fleet's email (W-021) | Owner (channel and assignee); mechanism proposed |
| W-035 | Classify every letter source's restrictions as access, storage or use, and record each on `letters.source`. Access restrictions (bots, gates) make the source `manual` (W-033). Storage restrictions mean extracts only (W-032). Use restrictions (no automated text analysis, text and data mining or AI) block model extraction entirely until the publisher consents in writing or a licence covers it; manual download does not lift them | Fundsmith's legal notice (re-read 2026-10-08) forbids, without express written consent, "any automated analytical technique aimed at analysing text and data in digital form to generate information". That binds whatever the collection route. Ruffer and Buy Side Digest have similar clauses | Proposed; compliance to rule |
| W-036 | Rate every ingested letter simply. The model judges two dimensions, Insight (original, argued, says where it parts from consensus) and Clarity, each 1 to 5 against written anchors with a one-line reason and a short quote. Two more are counted, not judged: Predictions (the number of explicit calls with a horizon, from W-037) and Uniqueness (embedding distance from the same quarter's letters). No overall score; the profile is shown and any one can sort. Calibration is a quick verdict (about right, too high, too low) on 10 rated letters, then thumbs up or down on any rating. Each rating records the model, prompt version and date | Owner's idea, 2026-10-08. The owner rejected a five-dimension rubric with 20 hand-scored letters as too heavy to keep up. Judging less and counting more also cuts model drift. Draft in `docs/RATINGS_AND_TAGS.md` | Owner (simplified rubric, 1-5 scale, no overall score) |
| W-037 | Extract each explicit call in a letter as a prediction record: subject (a security or topic id), direction, horizon, condition, confidence wording, quote. Track it from open to right, wrong, partly right or unresolvable; scored by a person at first, and automatically for price calls once a price source exists | Turns "clear predictions" into a track record for each writer by subject and horizon, which is worth more than a rating. Ties into W-007 | Proposed |
| W-038 | Classify managers with dated tags from a controlled list in five facets: kind (exactly one of manager, listed vehicle, independent writer, economist or strategist), style (value, deep value, quality, growth, special situations), strategy (long only, long/short, market neutral, activist, event driven, macro, credit and distressed, multi-strategy, crossover), and optionally asset focus and geography. Several tags per facet are allowed, except kind. The model may propose tags with evidence; a person ratifies them. Measured 13F facts (concentration, turnover, options use) sit beside the tags, never inside them. Supersedes the cohorts of W-026 | Owner's idea, 2026-10-08 ("tags to make it more loose"). One fixed list stops near-duplicates (W-018 reasoning). The 13F shows no shorts, so long/short and market neutral can only come from what managers say | Owner asked. Owner added crossover and kind and rejected real assets (2026-10-08); the rest of the vocabulary is proposed |
